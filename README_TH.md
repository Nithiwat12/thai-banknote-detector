# ตรวจจับธนบัตรไทยพร้อมเสียง — กล้องผ่านเบราว์เซอร์

## ติดตั้งและรัน
หยุดแอปเดิมด้วย Ctrl+C ก่อนแตก ZIP แทนไฟล์เดิม แล้วรัน:
```bash
python -m pip install -r requirements.txt
python -m streamlit run object_detection_app.py
```
เปิด http://localhost:8501 และกด Ctrl+F5 เพื่อโหลดหน้าใหม่

## ใช้งานหน้าเดียว
- ติ๊กช่อง “เปิดกล้อง” เพื่อเริ่ม (ปิดกล้อง = เอาติ๊กออก) แล้วอนุญาตกล้องในเบราว์เซอร์
- ตรวจจับเรียลไทม์ และ **พูดอัตโนมัติทันทีเมื่อพบธนบัตร** เช่น “หนึ่งร้อยบาท 2 ใบ” ไม่ต้องกดปุ่มใด ๆ
- ไม่มีปุ่มเปิดเสียง/อ่านซ้ำ/หยุดสำหรับกล้องแล้ว มีเพียงช่องติ๊ก “เสียงประกาศ” สำหรับปิดเสียง และเมนูเลือกเสียงไทย
- ไม่พูดรัว: หากผลเปลี่ยนจะพูดผลล่าสุดหลังประโยคเดิมจบ (มีหน่วงสั้น ๆ 1.5 วินาทีกันเสียงซ้ำจากภาพกระพริบ)
- ปรับความมั่นใจได้โดยกล้องไม่ต้องเริ่มใหม่
- อัปโหลดรูป/วิดีโอแล้วกด “ตรวจไฟล์ที่อัปโหลด” ยังใช้ได้เหมือนเดิม (จะปิดกล้องให้อัตโนมัติ)

## วิธีตรวจจับกล้อง (เรียลไทม์)
เบราว์เซอร์แสดงกล้องเอง แล้วส่งภาพ JPEG (ไม่เกิน 640 px) ตรงไปยังตัวตรวจจับในเครื่อง (detect_server.py)
ไม่ผ่านการรีเฟรชหน้าของ Streamlit จึงเร็วและต่อเนื่อง ส่งภาพทีละภาพ ได้ผลแล้วส่งภาพล่าสุดต่อ ไม่มีคิวสะสม
กรอบวาดบนภาพกล้องสด และพูดทันทีที่ได้ผลตรวจ ความเร็วขึ้นกับเครื่อง (CPU ธรรมดาได้หลายภาพต่อวินาที)
ตัวตรวจจับรับเฉพาะภาพที่ส่งมา ใช้พอร์ตสุ่มของเครื่อง (ไฟร์วอลล์ถาม ให้อนุญาตเฉพาะเครือข่ายส่วนตัว)
ถ้าเบราว์เซอร์ต่อพอร์ตตรวจจับไม่ได้ (เช่น deploy บน Streamlit Cloud) จะสลับไปส่งภาพผ่าน Streamlit เองอัตโนมัติ ใช้ได้แต่ช้ากว่ามาก
ใช้ Streamlit Cloud ต้องมีไฟล์ packages.txt (libgl1, libglib2.0-0) และเลือก Python 3.12

## เสียง
การติ๊กเปิดกล้องนับเป็นการกดของผู้ใช้ จึงปลดล็อกเสียงของเบราว์เซอร์ให้อัตโนมัติ ต้องมีเสียงภาษาไทยในเครื่อง (Chrome/Edge)
หากรายการเสียงมาช้า แอปจะรอแล้วเริ่มอ่านเมื่อพร้อม
ถ้าเสียงไม่ออก ให้ติ๊กเปิดกล้องใหม่ ตรวจเสียง Windows และการปิดเสียงแท็บ
เสียง online ของระบบอาจต้องมีอินเทอร์เน็ต แอปไม่ส่งภาพไปบริการเสียง

## ข้อจำกัด
กล้องเป็นของเบราว์เซอร์ผู้ใช้ ต้องใช้ localhost หรือ HTTPS และอนุญาตสิทธิ์กล้อง
HTTP ผ่าน IP เครือข่ายทั่วไปอาจเปิดกล้องไม่ได้
วิดีโออัปโหลดตรวจทีละเฟรม อาจช้ากว่าเวลาจริง ไม่เล่นเสียงต้นฉบับ
จำนวนใบมาจากกรอบหลังตัดกรอบที่เกือบตรงกัน อาจผิดหากโมเดลตรวจซ้ำ/จำแนกผิด โดยเฉพาะแบงก์ซ้อน
โมเดลเดิมไม่เปลี่ยน ไม่ได้เทรนใหม่หรือวัด accuracy ใหม่
ยังไม่ได้ทดสอบกล้อง/เสียงจริงบนเครื่องผู้ใช้

## ปรับความเสถียรเฉพาะกล้องสด (ฉบับนี้)
- กล้องใช้ confidence อย่างน้อย 0.60 แม้ slider ตั้งต่ำกว่า และปรับสูงกว่านี้ได้
- กรอบ นับใบ และเสียง ใช้ผลยืนยันอย่างน้อย 4 เฟรม ระยะเวลาอย่างน้อย 0.35 วินาที และคลาส 3 เฟรมล่าสุดตรงกัน
- จำนวนต้องคงเดิมอีก 0.25 วินาทีก่อนพูด เพื่อลดการประกาศจำนวนที่เปลี่ยนเร็ว
- ตัดกรอบเล็กมาก/ผิดรูปข้อมูล กรอบซ้ำเกือบตรงกัน และคลาสขัดแย้งที่ตำแหน่งเดียวกัน
- กรองภาพเบลอมาก (Laplacian variance < 10) และภาพมืดเดิม เกณฑ์นี้ยังไม่ได้จูนจากกล้องจริงของผู้ใช้
- ล้างกรอบเมื่อไม่พบหรือเชื่อมต่อล้มเหลว และซ่อนกรอบเก่าขณะรอผลนานกว่า 0.7 วินาที
- แยกประวัติแต่ละรอบเปิดกล้อง ไม่ปะปนผู้ใช้หรือรอบก่อน ทั้ง direct HTTP และ relay
- ภาพ/วิดีโออัปโหลดและน้ำหนักโมเดลคงจาก ZIP ล่าสุดของผู้ใช้
- ผลแรกจะช้าลงเล็กน้อยตามความเร็วโมเดลเพื่อยืนยัน ไม่ใช่การหยุดภาพกล้องสด
- ยังอาจผิดได้หากโมเดลจำแนกวัตถุอื่นเป็นแบงก์อย่างต่อเนื่อง ต้องเพิ่มภาพพื้นหลัง/กรณีผิดแล้วฝึกใหม่เพื่อแก้สาเหตุนั้น

ทดสอบตัวกรอง: python -m unittest test_confirmed test_detector_filter
